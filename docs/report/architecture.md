## 1. Сквозной контур (одним взглядом)

```
      A (лента 1 м/с, ФИКС., не останавливается)
      │
      ▼
┌───────────────┐   поток товаров ЛЮБОЙ плотности
│  НАКОПИТЕЛЬ    │   2 стоп-шибера (предгейт + эскейпмент):
│  (эскейпмент)  │   выпускает РОВНО ОДИН товар под конкретную каретку
└──────┬────────┘
       ▼
┌───────────────┐   3× RTX depth + макро-головка, слияние 3–5 чтений
│  ИЗМЕРЕНИЕ /   │   габариты (OBB) + признак «круг в сечении» (r/R≥0.8)
│  КЛАССИФИКАЦИЯ │   официальный порядок правил: габариты → форма
└──────┬────────┘   неуверенно → поток REVIEW (ручной разбор)
       ▼  класс + назначенная каретка (за 0.95+ с до дедлайна)
┌───────────────┐
│  ТИЛТ-ЛОТОЧНЫЙ │   9 кареток · шаг 600 мм · цепь 0.5 м/с
│  СОРТЕР        │   наклон ±38° — РЕАЛЬНЫЙ шарнир + серво (150 Н·м)
└──────┬────────┘   товар движется ТОЛЬКО контактной физикой
       ├── B: наклонный конвейер → инфид сортера (ФИКС.)
       ├── C: склиз 32° → ролл-кейдж 1200×800×800
       ├── D: склиз 32° → ролл-кейдж 1200×800×800
       └── REVIEW: склиз 32° → зона ручного разбора
```

Один и тот же механизм маршрутизирует **куб 11 мм** и **пуф 489 мм** —
размеронезависимый divert был главным критерием выбора исполнительной
схемы (толкатели/ARB-дефлекторы не управляют товаром 11 мм).

## 2. Часть определения и классификации

**Сенсорика.** Три RTX-depth головки (верхняя + два боковых профилировщика)
покрывают основной диапазон габаритов; **макро-головка** ближнего диапазона
довершает двух-диапазонную метрологию: пол сертификации мелочи — **10.8 мм**
(куб 11.0 мм измеряется и легально уходит в B, куб 10.0 мм консервативно
в C). Количество и состав камер — свободный выбор команды по ТЗ.

**Измерение.** По глубинным кадрам строится сегментация товара
(отделение от плоскости ленты), оценка ориентированного габарита и
признаков формы: круглость сечения, доля круглых сечений по оси,
купольность, элонгация. 3–5 чтений на товар сливаются в одно измерение
с оценкой уверенности (устойчивость к одиночному шумному кадру).
Доказуемость: конвейер экспортирует СВОЮ маску сегментации и облако
точек товара попиксельно к сохраненным кадрам
(`RTXPerception.export_masks` → `vision_mask_*.png` / `vision_cloud_*.npy`,
включая макро-головку) — панели жюри накладывают именно их, а не
повторную визуализационную сегментацию.

**Правила (исполняемая форма официальных).** Порядок в точности по ТЗ:
сначала габаритный гейт (>10×10×10, <450×320×320 c guard-band'ами на
сторону безопасности), затем «круг в любом сечении» через r_впис/R_опис ≥
0.8 по 19 станциям на каждую главную ось OBB. Приоритет: габариты выше
формы. Эталонная реализация — `tools/classify_mesh.py` (эксперт может
прогнать ЛЮБОЙ свой STL: `tools/expert_check.py`).

**Неоднозначные случаи.** Низкая уверенность/противоречивые чтения не
форсируются в основные категории — товар уходит в поток REVIEW (ручной
разбор), как это делается в промышленных системах. Это отдельная зона на
схеме компоновки (наше архитектурное дополнение к трём обязательным).

## 3. Связка частей: от класса к управляющему воздействию

1. Товар классифицирован ДО точки выпуска (ML работает с опережением —
   первый из двух канонических способов синхронизации из ТЗ).
2. Контроллер назначает товару конкретную каретку (по энкодеру цепи) и
   рассчитывает момент выпуска эскейпмента так, чтобы товар с ножа-передачи
   (полёт 110 мс, перепад 60 мм) сел в центр лотка; посадочное смещение
   логируется по каждому товару.
3. Команда наклона выставляется заранее; исполняется на позиционном гейте
   станции. **Задержка команда→начало движения 40 мс; минимальный запас
   между готовностью команды и дедлайном по всей матрице — 0.95 с.**
4. Подтверждение схода: боковой конфирм + контроль плоскостности лотка;
   таймауты зависят от длины товара. Если устье занято (фотоэлемент
   устья) — выпуск ДЕРЖИТСЯ на эскейпменте (накопитель и есть буфер),
   каретка не разгружается в занятый лоток.

Темп: шаг кареток 600 мм при 0.5 м/с ⇒ такт 1.2 с/товар
(теоретический потолок ~3000 шт/ч на одну линию выпуска); лента A при
1 м/с никогда не останавливается — развязку темпов обеспечивает
накопитель.

## 4. Исполнительная часть: физическая честность

- Каретки — кинематические тела на серво-цепи (как у реального сортера);
  **лоток — динамическое тело на настоящем револьвентном шарнире** с
  угловым приводом (150 Н·м из массового расчёта, 160°/с).
- Товар движется **только контактной физикой**: гейт
  `direct_velocity_writes_nominal = 0` во всех прогонах. Никаких
  телепортов, невидимых сил и скриптованных траекторий.
- Бережное обращение: худшая контактная точка цикла 2.5–3.4 g — на
  порядок ниже транспортных норм (§8.1 расчётов).
- Нештатные сценарии в исполнении: дрель заклинивания (fault_jam),
  отказ лотка (fault_tray), подозрительная каретка (purge), занятое
  устье (hold-at-escapement) — все с восстановлением и метриками.

**Механическая достоверность (аудиты).** Помимо физического аудита
коллайдеров (0 нарушений, вкл. полную геометрию звеньев манипулятора),
сборка проходит **визуальный аудит заметённого объёма**
(`isaac/audit_visual_sweep.py`): каждый прим сцены — включая
декоративные — проверяется против качания лотка 0/25/50/75/100% в обе
стороны, аварийного предела ±46°, обратной ветви и коридоров падения
товара. Итог перестройки каретки: **64 пересечения → 0** при неизменных
метриках физики (паритет seed42 подтверждён). Силовая цепь каретки
непрерывна: звено цепи → хребтовая балка → сёдла-подшипники → вал →
серьги лотка.

## 5. Цифровой двойник (MuJoCo) и паритет

Полный независимый двойник (`cell/`) на MuJoCo: та же геометрия из
`cell/params.py`, тот же контроллер, те же правила. Роль:
1) CPU-fallback для проверки экспертами без GPU;
2) кросс-валидация физики (иная контактная модель);
3) быстрые итерации контроллера до дорогих RTX-прогонов.
Формальные записи двойника: **22/22 прогона, 235 товаров, 0 отказов**.

## 7. Карта исходников

| Путь | Ответственность |
|---|---|
| `cell/params.py` | ЕДИНЫЙ источник геометрии/настроек обеих симуляций |
| `cell/` | цифровой двойник MuJoCo (CPU): сцена, контроллер, прогоны |

| `isaac/audit_visual_sweep.py` | визуальный аудит заметённого объёма |
| `tools/classify_mesh.py` | эталонные официальные правила для любого STL |

## 8. Ограничения и развитие

- Обратная ветвь возит только пустые каретки (занятые держатся выпуском
  на эскейпменте); рециркуляция занятых потребовала бы карусельной
  топологии — осознанный размен в пользу компактной линейной.
- Горло устья 14.1 мм (фаска) — валидированный лабиринтный интерфейс;
  расширение до 15 мм потребовало доработки таймаута удержания устья и
  отложено (задокументировано в `cell/params.py`).
- Следующий шаг зрелости — физический прототип одной каретки с
  серво-наклоном (материалы кинематики и спецификация узлов уже
  достаточны для изготовления).
