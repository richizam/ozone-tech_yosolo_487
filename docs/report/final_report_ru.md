# Итоговый отчет — SortMaster
## Трек 3: Интеллектуальная роботизированная система сортировки товаров

> Программно-аппаратный комплекс (ПАК), выполненный **полностью в симуляции**
> двумя физическими движками: NVIDIA Isaac Sim 6.0.1 (PhysX 5 + RTX-сенсоры,
> высокоточный цифровой двойник) и MuJoCo 3 (детерминированный валидационный
> двойник той же ячейки). Классификация — по официальным правилам, в движении,
> до точки сброса; исполнительная часть — **линейный сортировщик с поворотными
> лотками** (tilt-tray): захват из накопителя эскейпментом, синхронная укладка
> на лоток, гравитационный сброс в зону B/C/D. Ноль прямых записей скорости
> товару в штатном цикле (`direct_velocity_writes_nominal = 0` — жесткий гейт).

## 1. Постановка, границы и терминологический мост

Решение работает на участке СЦ до основного сортировщика (см.
`doc-1783095831.pdf`): подающий конвейер **A** (фиксирован, 1 м/с, без
остановок в базовом сценарии, вход до 500×500×500 мм) заканчивается
**накопителем**, из которого исполнительная часть забирает товар и физически
направляет его в одну из зон: **B** (основной сортировщик, фиксирован),
**C** (негабарит, ролл-кейдж 1200×800×800), **D** (доупаковка, ролл-кейдж).
Рабочая зона 6000×10000 мм; свободные элементы размещены внутри нее
(проверяется автотестом `test_everything_inside_the_work_zone`).

Соответствие терминов задачи и узлов нашей ячейки:

| Термин задачи | Узел ячейки |
|---|---|
| Накопитель | Буферная зона эскейпмента в конце конвейера A: нормально-закрытая стоп-пластина, перед которой товары становятся доступны исполнительной части; выпуск строго по одному, синхронно с пустым лотком |
| Исполнительная часть | Эскейпмент + линейный tilt-tray сортировщик (9 кареток, шаг 0.6 м, 0.5 м/с) + гравитационные тормозные желоба + исключительный манипулятор (только разбор застреваний) |
| Точка A | Подающий конвейер (фиксированный, 1 м/с) |
| Точка B | Наклонный приводной конвейер-коннектор → фиксированная лента основного сортировщика |
| Точки C, D | 32°-желоба → ролл-кейджи с апертурными стенками |
| Неоднозначные случаи | Отдельная полоса REVIEW (ручной разбор) — как рекомендовано в справочном разделе постановки |

## 2. Часть определения и классификации товара

### 2.1 Подход: геометрическая метрология, а не черный ящик

Официальные правила чисто геометрические, поэтому категория **вычисляется из
измеренной геометрии** по формальным критериям — объяснимо в каждом
пограничном случае. Товар измеряется **в движении** (лента не останавливается)
станцией из четырех рендеренных RTX-глубинных камер (окно x 5.65–6.05 м):

* **обзорная метрологическая камера** (1024×768) — габариты сверху;
* **две боковые профильные камеры** — вертикальность боковой стенки
  (лежащий цилиндр/шестигранник наклонен, стенка коробки вертикальна);
* **макро-камера ближнего действия** (768×768, GSD ≈ 0.4 мм) — включается,
  когда минимальный габарит с обзорной камеры < 25 мм.

### 2.2 Правила (приоритет — как в постановке)

1. **Сначала габариты**: любой размер < 10 мм (недомер) или превышение
   450×320×320 мм (перемер) → категория «Не подходит по габаритам» → **C**.
   Перемерный цилиндр уходит в C, а не в D — приоритет правил соблюден.
2. **Затем форма**: круг в сечении по формальному критерию
   `r_вписанной / R_описанной > 0.8` → «Требует доупаковки» → **D**.
3. Иначе → «Подходит для сортировки» → **B**.

**Метрологические охранные полосы (guard bands).** Сертификация «больше
10 мм» честна только с учетом разрешения измерителя: порог недомера =
10 мм + 2×GSD → **16 мм** для обзорной камеры и **10.8 мм** для макро-камеры.
Куб 11 мм сертифицируется как сортируемый (B) ТОЛЬКО потому, что его измерила
макро-камера; куб 10 мм и стержень Ø9 мм уходят в C. Перемер проверяется по
нижней доверительной границе размеров (25-й перцентиль по чтениям) — смаз
кадра не может «раздуть» товар в перемер.

**Политики безопасной стороны.** Решающие правила консервативны ПО
ПОСТРОЕНИЮ: нет валидных чтений → D; вытянутый предмет с неподтвержденным
сечением → D; слабая, но устойчивая круговая улика → D; сомнение в захвате
кадра (обрезанное/устаревшее облако) → кадр отбрасывается целиком; ни одна
неуверенность не может выбрать разрешающую ветку.

Честная формулировка границы: консервативны **политики**, а измерение имеет
конечную точность, и вблизи порогов её компенсируют охранные полосы,
рассчитанные под разрешение каждой головки. На официальном и пограничном
наборах это подтверждено полностью — **ноль разрешающих ошибок во всех 15
прогонах Isaac и 22 прогонах твина**. На нарочно враждебных СЛУЧАЙНЫХ телах
(кампания «неизвестных форм», см.
[unknown_shape_campaign.md](unknown_shape_campaign.md)) мы сами нашли два
класса, где одиночное чтение CPU-твина занижает признак и уходит в B
(гранёная призма; тонкий стержень у границы перемера) — ограничение
задокументировано вместе с планом устранения, а не спрятано.

### 2.3 Проверки и разбор ошибок

* Официальный набор из 11 STL: классификация **1.0 (66/66, 6 сидов)** на
  номинальных прогонах Isaac (6 сидов), воспроизводимо по сидам.
* Пограничный набор (создан скриптами, размеры документированы): кубы 11/10 мм,
  стержень Ø9, карта 2 мм, коробки 445/460 мм, r/R 0.78/0.82, стержень
  16×12 мм — поведение каждого зафиксировано в матрице валидации.
* Разобранные консервативные решения (документированы как проектные):
  `bl_rod_b` (сечение 16×12 на пороге разрешения флангового датчика) → D;
  `bl_rsq_b` (r/R = 0.78, в 0.02 от порога) → D при стресс-нагрузке;
  сросшиеся облака при плотном потоке → C/REVIEW. На всём валидированном
  наборе ни одна ошибка не ведёт в B.
* **Кампания на неизвестных формах** (30 процедурных тел × 2 позы,
  воспроизводится одной командой): нашла 2 пермиссивных случая — и оба
  **закрыты с замером**. Лежащая шестигранная призма обходила сечение по
  главной оси (почти квадратный след → вырожденная ось PCA); закрыто
  **развёрткой сечений по 12 осям** — официальное правило и есть «круг в
  сечении по ЛЮБОЙ оси». После закрытия призма читается r/R = 0.89 в
  обоих движках (двойник и RTX Isaac — одинаковое число с реальных
  сенсоров). Второй случай оказался дефектом испытательного стенда
  (объект фотографировался в полёте после заглублённого спавна),
  исправлен в стенде. Итог: **0 пермиссивных из 60**, согласие с
  правилами 73%, остальные расхождения — консервативные по политике
  безопасной стороны — [unknown_shape_campaign.md](unknown_shape_campaign.md).
  Это наш ответ на вопрос о приватном наборе жюри: не «архитектура
  защищает», а собственная адверсарная кампания, найденные ошибки и
  замеренное закрытие. Наглядно — облака точек сенсора с измерением и
  решением: [figures/clouds/](figures/clouds/).
* **Двухдиапазонная метрология мелкого товара** (закрытие по итогам
  QA-сессии экспертов: игральная кость 12 мм — легальный сортируемый
  товар, а мелкий круглый не должен попасть в сортировщик ни при каких
  условиях). Обзорная головка (3 мм/px) физически не разрешает форму
  тела 12–15 мм, поэтому в обоих движках у измерительного туннеля есть
  ближняя МАКРО-головка (0.4 мм/px): плотное облако, зеркальное
  hull-сечение (квадрат 0.707 на любом срезе, круг ~1.0) и пол
  сертификации 10 + 2·GSD = 10.8 мм. Результат на целевой сюите
  (кость 12/куб 11 → B; куб 10/стержень Ø8 → C; сфера Ø12, цилиндры
  Ø12–15 лёжа, шестигранник 15 → D): **32/32**; кампания неизвестных
  форм после закрытия — согласие 44/60 (было 40/60) при прежнем нуле
  пермиссивных. Облака и решающие сечения мелкого диапазона — в том же
  каталоге фигур (`cloud_die_12mm`, `cloud_cyl_12x40`,
  `cloud_sphere_12mm`).
* **Precision/Recall по категориям** (официальная метрика качества по
  ответу экспертов от 21.07) — из запечатанных матриц, полная таблица в
  [classification_pr.md](classification_pr.md). Номинальные прогоны Isaac:
  **P = R = 1.0 по всем трём категориям** (66 товаров). По ВСЕЙ матрице,
  включая пограничный атакующий набор и аварийные дрели (150 рутинных
  решений + 8 исключений): **precision(B) = 1.0 — ни одного ложного B
  нигде и никогда**; recall(B) 0.89 — недобор целиком за счёт
  спроектированных консервативных отводов пограничных тел; C 0.96/0.98,
  D 0.93/0.99.
* **Товар меньше 10×10×10 мм НА ВХОДЕ — штатный случай** (Q&A: «товар
  меньшего размера может рассматриваться как объект, поступивший на
  участок ПАК… должен быть направлен в C»). Ровно это покрывает наш
  пограничный набор: карта 2 мм (тоньше отсекателя → спроектированные
  поддонные терминалы с вызовом оператора), стержень Ø9 и кубик 10 мм —
  все сертифицируются в C по полу измерителя, ни один не может уйти в B.
* **Неуверенная классификация — это НЕ категория** (позиция экспертов от
  23.07: неуверенный результат нельзя молча записывать в штатные C/D).
  В ячейке этому соответствует отдельный поток исключений: REVIEW-полоса
  (физически отдельный загон с ручным разбором), вызовы оператора и
  поток доупаковки с повторной подачей. В метриках такие товары считаются
  исключениями отдельной строкой, а не «правильными C/D» — см. колонку
  «→ exceptions» в таблице P/R.

## 3. Исполнительная часть

### 3.1 Почему поворотные лотки

Правила делают куб 11 мм **легальным сортируемым товаром**. Роликовый
дивертер (ARB) физически не управляет предметами меньше ~50–75 мм (шаг
роликов). У tilt-tray сортировщика товар едет **на собственном лотке** и
сбрасывается гравитацией — сброс **не зависит от размера**: куб 11 мм и пуф
489 мм проходят одинаково. «Поворотные лотки» — класс механизмов, прямо
названный в постановке; это же решение используется в реальной посылочной
сортации.

### 3.2 Полный цикл (все контактной физикой)

выпуск эскейпмента (синхронно с пустым лотком) → сход с ножевой кромки
(падение 60 мм, оффсет посадки измеряется по каждому товару) → перевозка на
подвешенном на реальном шарнире лотке (привод: позиционный, задержка 40 мс,
рампа 160°/с, шум усиления 1%) → позиционный триггер сброса → гравитационный
сход: C/D — юг, в 32°-желоба с полированным листом (μ/tg32° = 0.45 — ничего
не может остановиться на склоне), тормозной площадкой и ролл-кейджем с
апертурой; B — север, через приводной наклонный коннектор (16.6°, товар
держится трением: категория B по правилам не содержит круглых) на
фиксированную ленту; REVIEW — север, в загон ручного разбора. Лоток
возвращается в горизонталь — цикл замкнут (возврат механизма в исходное
состояние — критерий рубрики).

### 3.3 Расчеты ↔ симуляция

Каждый механизм обоснован аналитически и сверен с измерениями в симуляции
(полная сверка: `docs/report/calculations_vs_simulation.md`): угол сброса
38° > угла трогания 17.7°; синхронизация выпуска (модель разгона, в т.ч.
**качения** для лежащих стержней: a_roll ≈ 0.42·a_slide); запас команды
(command margin) ≥ 1.05 с; скорость входа в кейдж ≈ 2.3 м/с с
тормозной площадкой; удержание на наклоне B (0.55 > 0.30); сертификация
мелочи (пол 10.8 мм); производительность.

### 3.4 Нештатные ситуации — у каждого отказа спроектированный безопасный терминал

| Отказ | Реакция (все в матрице валидации) |
|---|---|
| Неуверенная классификация | Полоса REVIEW, не B |
| Товар не сел на лоток (промах индукции) | Каретка и ее сосед помечаются «подозрительными» → профилактический сброс в REVIEW на следующем круге |
| Сброс не подтвержден | Таймаут «застрявшего наклона» → выравнивание → повтор на следующей станции / REVIEW |
| Мертвый привод лотка (дрель `--inject-tray-fault D`) | Товар доезжает до конца линии → вызов оператора (end-line call-out) |
| Застревание в желобе (дрель `--inject-jam`) | Ноль-смещение-вотчдог → джем-камера локализует → манипулятор переносит маршрутно-корректно в СВОЙ кейдж; станция блокируется на время работ |
| Сход мимо устья (поздний/короткий сброс) | Аварийные поддоны вдоль обоих флангов сброса (южный охватывает пьедестал манипулятора воротником 8 мм, южный борт 120 мм, демпфирующая накладка): товар ложится НА поддон — пол конструктивно недостижим — вотчдог поддона вызывает оператора |
| Мягкий товар не соскальзывает → повтор в REVIEW → боковое скатывание к соседней апертуре | Перегородка-фин 6 мм в стыке между устьем REVIEW и приводным коннектором B (зазор 12 мм до обоих качаний лотков, подтверждено аудитом): физически исключает попадание D-товара на ленту основного сортировщика — единственное запретное направление ошибки |
| Промах индукции мелкого товара мимо поддона | Ступенчатый южный козырёк поддона (z 0.36, только в окнах без устий под ним — в коридор сброса попасть не может по построению): куб 10 мм ложится на козырёк → вызов оператора, не пол |
| Затор на коннекторе B (дрель) | Вызов оператора, без вмешательства манипулятора |
| Плотный поток / сдвоенная посадка | Спейсинг-гейт + REVIEW при двойной занятости |

### 3.5 Безопасность эксплуатации

Ячейка ограждена, доступ человека — через световую завесу с цепью аварийного
останова; манипулятор стоит на пьедестале в сервисном коридоре МЕЖДУ
желобами C и D (вне объемов всех кейджей) и никогда не пересекает их стенки:
возвращенный товар отпускается на линию желоба СНАРУЖИ стеночной плоскости
и заезжает в кейдж через штатную апертуру — желоб и есть «дверь» кейджа.
Привод наклона рассчитан по худшему удару посадки свипа массы 1.3×
(насыщение 150 Н·м). Зазоры механизма проверяет автоматический аудит
(isaac/audit_clearance.py): полный цикл наклона на каждой станции + конверт
траекторий манипулятора против всей статики, порог 15 мм, ненулевой выход
при нарушении. Все
вызовы оператора выводятся на HMI-лампы станций и андон-колонну; сервисный
режим — пониженная скорость. (Модель ограждений и HMI — в презентационном
слое сцены.)

## 4. Связь частей: категория → управляющее воздействие

Цепочка на каждый товар (пишется в `events.csv` каждого прогона):
`item_classified` (вердикт + уверенность, **до** эскейпмента — упреждение
скрывает латентность инференса) → `escapement_release` (выбор конкретного
пустого лотка по петлевой координате, модель разгона по классу товара) →
`induction_landed` (оффсет посадки, мм) → `routing_cmd` → `tilt_cmd` (момент
позиционного триггера, с упреждением по измеренной длине) → `tilt_full` →
`discharge_confirmed` (подтверждение стороной сброса) → `item_delivered` +
`containment_final`. Запас времени между готовностью команды и дедлайном
триггера — **command margin** — измеряется по каждому товару; минимум по
матрице 1.05 с (отрицательный запас валит прогон ненулевым кодом).

### 4.1 Промышленный контур управления (проектная логика)

По ответу экспертов от 21.07 (PLC/HMI не обязательны для sim-first, но
проектная логика контура повышает инженерную реалистичность) фиксируем
контур в терминах датчики → сигналы → приводы:

* **Датчики.** 4 RTX-глубинные головки измерительного туннеля (обзорная
  1024×768, две боковые 768×576, макро 768×768, кадость 8.3 Гц);
  джем-камера зоны желобов; энкодерная одометрия цепи сортировщика
  (проверка 2 Гц, максимум расхождения пишется в каждый summary);
  позиционные триггеры станций — по той же одометрии.
* **Сигналы.** Вердикт классификации (латентность инференса 80 мс,
  модель) → команда маршрута лотку → позиционный триггер станции →
  команда наклона (задержка привода 40 мс, рампа 160°/с, шум усиления
  1%) → подтверждение сброса стороной станции → возврат в горизонт.
  Каждый переход — строка `events.csv`; счётчик прямых записей скорости
  обязан быть нулём (жёсткий гейт).
* **Приводы.** Отсекатель-эскейпмент и удерживающие ножи (пневмокласс,
  ход 186 мм); 9 наклонных сервоприводов лотков; ленточные приводы
  (лента A 1 м/с, коннектор B, разгрузочные жёлобы 0.8 м/с);
  4-осевой манипулятор разбора нештатных ситуаций.
* **Безопасность.** Аварийные остановы на стойке HMI и восточном
  ограждении (сцена); блокировка станции при работе манипулятора
  (out-of-service поток с перемаршрутизацией); политика
  lockout/tagout — отказ локализации под кожухом жёлоба не разбирается
  вслепую, а эскалируется оператору; каждый отказной терминал закрыт
  геометрией (поддоны/фартуки/перегородки), пол конструктивно
  недостижим.

## 5. Производительность и временная согласованность

* Темп ленты 1 м/с, лента не останавливается: `conveyor_a_stop_count = 0` —
  метрика в каждом прогоне.
* Пропускная способность: ≈ 480–500 товаров/час на официальной смеси
  (кейс масштабирования — параллельные ячейки, см. отчет по потоку).
* **Честная арифметика официального такта** (Q&A: ориентир потока
  ≈ 1.4 шт/с ≈ 5000 шт/ч; цикл захвата «не хуже ~0.7 с»). Одна ячейка
  SortMaster держит такт 7.3 с/товар — его задаёт измерительный туннель
  в движении и одиночная дисциплина эскейпмента, а не механика сброса
  (сам сброс — 1.2 с/лоток). Ни одна одиночная ячейка известной нам
  архитектуры (pick&place 2–4 с/товар) такт 0.7 с тоже не держит —
  постановка сама предусматривает выход: «если ПАК не успевает в такт,
  товары накапливаются в накопителе; команда должна показать работу с
  накоплением» — что мы показываем ЗАПЕЧАТАННЫМ прогоном
  `overload_feed` (подача с официальным периодом, 0 опасных / 0 на пол
  / 0 дедлоков / лента ни разу не остановилась). Закрытие такта в
  полном масштабе — тиражирование ячеек: N параллельных ПАК по
  ≈ 490 шт/ч дают ≈ N × 490 шт/ч (10–11 ячеек ≈ 5000 шт/ч); зоны C/D
  и их кейджи по Q&A могут дублироваться в пределах рабочей зоны, а
  распараллеливание по ячейкам не требует связи между ними (у каждой
  свой измерительный туннель и свои терминалы).
* Cycle time (полный цикл: классификация → решение → физическая доставка),
  p95 по сценарию — из `summary.json` каждого прогона:

  | Сценарий | p95, с (Isaac) | p95, с (MuJoCo-твин) |
  |---|---|---|
  | Номинал (6 сидов) | 7.24–7.43 | 7.79–8.46 (сид 99: 14.9 — увод в вызов оператора) |
  | Пограничный набор | 8.6–24.8 | 8.9 |
  | Плотный поток | 7.0 | 7.7 |
  | Аварийные дрели | 7.3–16.6 | 20.9–27.3 |

  Разброс между движками — контактные модели, а не разные сценарии;
  длинные хвосты — это по построению сценарии атаки и восстановления.
* Синхронизация: классификация в движении с упреждением; актуатор — задержка
  40 мс + рампа 160°/с + шум 1%. Посадочный оффсет: медиана номинала
  ≈ 80–130 мм, **максимум по всей матрице 138.8 мм** (сид 2, номинальный
  прогон) при полуширине лотка 310 мм — запас более 2× даже в худшем
  случае.
* **Официальная проверочная каденция** (ответ экспертов от 21.07: лента
  1 м/с, расстояние между товарами 1 м, подача непрерывная — период
  прихода (1.0 + длина)/v = 1.15–1.5 с, ~5× быстрее такта ячейки).
  Эксперты явно относят накопление к спроектированному перегрузочному
  режиму. Дрель `overload_feed` (артефакты —
  `validation/runs/overload_feed_s42/`): весь официальный набор из 11 тел
  подан с этим периодом — **0 опасных, 0 на пол, 0 дедлоков, лента не
  остановилась ни разу, 11/11 доставлены**. Очередь копится на ленте A
  против удерживающих ножей (лента проскальзывает под задержанным
  товаром), измерительное окно остаётся однотоварным, обработка идёт в
  такте ячейки; часть стеснённых измерений уходит в потоки исключений
  (консервативная сторона) и точность восстанавливается при возврате к
  такту. Это и есть заявленное поведение «нештатного/перегрузочного
  сценария», а не деградация врасплох.

## 6. Валидация (два движка, одна ячейка)

**Претензия уровня готовности (по критериям УГТ и разъяснению экспертов
от 21.07):** исполнительная часть — «валидированная цифровая модель,
сопоставленная с расчетами»: каждый механизм сверен с аналитикой
(`calculations_vs_simulation.md` — углы, синхронизация, запасы, скорости
входа), допущения и границы перечислены (раздел 8), а независимый второй
движок исключает артефакты одного солвера. Это дословно та формула,
которой эксперты определяют L4; финальную оценку выносят они.

**3D-модели и материалы уровня L3** (модель ячейки, узлы, спецификация,
кинематика): полная 3D-модель участка существует в двух инженерных
форматах, порождаемых из одного источника параметров — MJCF
(приложен: [cell_model.mjcf.xml](cell_model.mjcf.xml), 256 геометрий /
49 суставов, включая оба ролл-кейджа 1200×800×800 с колёсами и
апертурой) и USD (строится `isaac/scene_usd.py` в официальном
контейнере; экспорт сцены — в облачном хранилище). Спецификация узлов —
сам `cell/params.py`: каждый размер, ход, задержка и допуск машины
объявлены в одном файле с пояснениями. Ролл-кейджи — намеренно ТИПОВАЯ
оборотная тара (позиция экспертов от 21.07: кастомный кейдж не
рекомендуется, допустимо упрощение до ёмкости 1200×800×800), поэтому
отдельные CAD-модели контейнеров не требуются — вся механика подачи
находится на стороне ПАК.

**Isaac Sim (основной твин, RTX-сенсоры в контуре):** матрица из 15 прогонов
— 6 номинальных сидов, 2 прогона пограничного набора, 4 робастность-свипа
(трение 0.7×, масса 1.3×, плотный поток, смещенная подача), 2 аварийные
дрели. Итог: 15/15 прогонов, **GATES: PASS** — номинальная классификация 1.0
(66/66), номинальная маршрутизация 1.0, 0 опасных ошибок, 0 падений на пол,
удержание 1.0, 0 прямых записей скорости, min запас команды 1.05 с, куб
11 мм (связывающий габарит измерен 11.0 мм при пороге 10.8) доставлен в B.
Жесткие гейты консолидации: классификация ≥ 0.98 (номинал), маршрутизация
≥ 0.97 (номинал), **0 опасных ошибок, 0 падений на пол, удержание 1.0,
0 прямых записей скорости, запас команды > 0, куб 11 мм физически доставлен
в B**.

**Свипы деградируют — честно и в безопасную сторону.** Гейты точности
намеренно применяются к номиналу: сценарии-атаки меняют попадание в
идеальную зону на безопасность, и КАЖДОЕ отклонение уходит в
консервативный терминал (C / D / REVIEW / вызов оператора), никогда в
разрешающую сторону. Маршрутизация по прогонам (полные артефакты —
`isaac_evidence/xbelt/matrix/`):

| Прогон | Маршрутизация | Чем объясняется |
|---|---|---|
| 6 номинальных сидов | **1.0** | 66/66 |
| Плотный поток, масса 1.3×, дрель заклинивания | 1.0 | стресс без потери точности |
| Смещенная подача | 0.909 | 10/11, один консервативный увод |
| Дрель отказа лотка | 0.818 | мертвый привод → штатный вызов оператора |
| Пограничный набор (20 предметов) | 0.70 | набор специально спроектирован против правил |
| Мелочь у порога | 0.667 | под полом сертификации → C по правилу |
| Трение 0.7× | 0.636 | худший случай; 0 опасных, 0 падений |

**MuJoCo (валидационный твин):** матрица 22 прогона × гейты
(22/22 прогона PASS, 235 товаров, 0 отказов), детерминирован, воспроизводим
на машине жюри без GPU (`docker compose up`). В номинале классификация 1.0
на всех шести сидах; маршрутизация 1.0 на пяти сидах и 0.909 на сиде 99 —
единственное отклонение — **безопасный вызов оператора**
(`operator_callouts: 1`, `unsafe_errors: 0`), спроектированный терминал, а
не ошибка сортировки. Совпадение физических огибающих двух движков —
самостоятельное свидетельство валидности (посадочные оффсеты, времена
наклона, скорости входа в кейджи).

Историческая честность: пройденный путь отладки (провал маленького предмета
в дискретный зазор, «совок» при выравнивании лотка, клин тонкой оболочки)
задокументирован в `isaac/README.md` и коммитах — каждый дефект закрыт
проектным решением и **закреплен автотестом-инвариантом** (72 теста).

## 7. Проверка экспертами

Одна команда — вся матрица с гейтами (выход ненулевой при любом провале):

```bash
# MuJoCo (любая машина, CPU):
python -m cell.validate --matrix configs/validation_matrix.yaml
# Isaac (GPU-сервер, официальный контейнер isaac-sim:6.0.1):
bash isaac/run_matrix.sh /out/xbelt_matrix && python3 tools/consolidate_isaac_matrix.py /out/xbelt_matrix
```

Параметры, доступные эксперту: `--seed`, `--items` (любой поднабор, в т.ч.
пограничные), `--manifest-extra` (кубы 11/10 мм и др.), `--spawn-gap`,
`--spawn-offset-y`, `--friction-mult`, `--mass-mult`, `--inject-jam SLUG@Y`,
`--inject-tray-fault ZONE`, `--record` (видео), `--depth-stills` (кадры
сенсоров). Полная инструкция: `README.md §8`, `isaac/README.md`.

**Свой STL эксперта:** `python tools/expert_check.py model.stl` — класс и
полная трасса решения по официальным правилам; с ключом `--register` товар
регистрируется и прогоняется через ФИЗИЧЕСКИЙ контур в обоих движках.

## 8. Упрощения модели — полный перечень

По требованию ТЗ упрощения перечислены явно и обоснованы. Ни одно из них не
касается критического утверждения работы: **товар в штатном цикле движется
только контактной физикой** (`direct_velocity_writes_nominal = 0` — гейт).

| Упрощение | Где | Обоснование и граница |
|---|---|---|
| Тяговая цепь сортировщика позиционно-управляемая (кинематика по расписанию цепи) | оба движка | Так работает и реальная серво-цепь: скорость трассы задаётся приводом, а не трением. Силовая часть — лоток, шарнир, привод, ВСЕ контакты с товаром — динамическая. Границы: `isaac/README.md` |
| **Модель ленты в MuJoCo-твине**: поверхность задаёт скорость товару напрямую (`drive_writes`, считаются ОТДЕЛЬНО от `direct_velocity_writes`), с центрирующим членом v_y = 0.8·(y_ленты − y) и «teeter»-участком у ножа | только твин (`cell/belt.py`) | Классическая абстракция конвейера в MuJoCo (нет ленточного примитива). **В Isaac Sim лента — настоящая PhysX surface velocity с трением**, поэтому именно основной твин доказывает физику переноса; MuJoCo-твин отвечает за детерминированную проверку логики и контроллера на CPU. Совпадение огибающих двух моделей — проверка самой абстракции |
| Интерлоки читают состояние симуляции: занятость окна измерения, контроль ухода шибера, фотоэлемент устья, вотчдог заклинивания, подтверждение схода, identity-gate перцепции | оба движка | Абстракции промышленных датчиков (фотоэлементы, энкодеры цепи, контроль положения шибера) — в железе это реальные компоненты. **Категория товара так не получается никогда**: она вычисляется только из отрендеренной глубины (проверяется автотестом на отсутствие утечки эталона) |
| Мягкие товары (мешок, пуф) — жёсткие аппроксимации с материалами повышенного трения/демпфирования | оба движка | Худший случай по отскоку/скольжению; деформация в пользу удержания не учитывается |

## 9. Развитие

* Физический стенд одного модуля лотка — наибольший прирост УГТ; материалов
  кинематики и спецификации узлов достаточно для изготовления.
* Сканер штрихкодов в станции измерения (категория ВСЕГДА остаётся за
  формальными правилами — сканер только для трассируемости).
* Обучаемый детектор для трекинга и предсказания заторов.
* Обратная ветвь возит только пустые каретки; рециркуляция занятых
  потребовала бы карусельной топологии — осознанный размен в пользу
  компактной линейной.
