# Итоговый отчет — SortMaster
## Трек 3: Интеллектуальная роботизированная система сортировки товаров

> Программно-аппаратный комплекс (ПАК), выполненный **полностью в симуляции**
> двумя физическими движками: NVIDIA Isaac Sim 6.0.1 (PhysX 5 + RTX-сенсоры,
> высокоточный цифровой двойник) и MuJoCo 3 (детерминированный валидационный
> двойник той же ячейки). Классификация — по официальным правилам, в движении,
> до точки сброса; исполнительная часть — **линейный сортировщик с поворотными
> лотками** (tilt-tray): захват из накопителя эскейпментом, синхронная укладка
> на лоток, гравитационный сброс в зону B/C/D. Ноль прямых записей скорости
> товару в штатном цикле (`direct_velocity_writes_nominal = 0` — жесткий гейт).

## 1. Постановка, границы и терминологический мост

Решение работает на участке СЦ до основного сортировщика (см.
`doc-1783095831.pdf`): подающий конвейер **A** (фиксирован, 1 м/с, без
остановок в базовом сценарии, вход до 500×500×500 мм) заканчивается
**накопителем**, из которого исполнительная часть забирает товар и физически
направляет его в одну из зон: **B** (основной сортировщик, фиксирован),
**C** (негабарит, ролл-кейдж 1200×800×800), **D** (доупаковка, ролл-кейдж).
Рабочая зона 6000×10000 мм; свободные элементы размещены внутри нее
(проверяется автотестом `test_everything_inside_the_work_zone`).

Соответствие терминов задачи и узлов нашей ячейки:

| Термин задачи | Узел ячейки |
|---|---|
| Накопитель | Буферная зона эскейпмента в конце конвейера A: нормально-закрытая стоп-пластина, перед которой товары становятся доступны исполнительной части; выпуск строго по одному, синхронно с пустым лотком |
| Исполнительная часть | Эскейпмент + линейный tilt-tray сортировщик (9 кареток, шаг 0.6 м, 0.5 м/с) + гравитационные тормозные желоба + исключительный манипулятор (только разбор застреваний) |
| Точка A | Подающий конвейер (фиксированный, 1 м/с) |
| Точка B | Наклонный приводной конвейер-коннектор → фиксированная лента основного сортировщика |
| Точки C, D | 32°-желоба → ролл-кейджи с апертурными стенками |
| Неоднозначные случаи | Отдельная полоса REVIEW (ручной разбор) — как рекомендовано в справочном разделе постановки |

## 2. Часть определения и классификации товара

### 2.1 Подход: геометрическая метрология, а не черный ящик

Официальные правила чисто геометрические, поэтому категория **вычисляется из
измеренной геометрии** по формальным критериям — объяснимо в каждом
пограничном случае. Товар измеряется **в движении** (лента не останавливается)
станцией из четырех рендеренных RTX-глубинных камер (окно x 5.65–6.05 м):

* **обзорная метрологическая камера** (1024×768) — габариты сверху;
* **две боковые профильные камеры** — вертикальность боковой стенки
  (лежащий цилиндр/шестигранник наклонен, стенка коробки вертикальна);
* **макро-камера ближнего действия** (768×768, GSD ≈ 0.4 мм) — включается,
  когда минимальный габарит с обзорной камеры < 25 мм.

### 2.2 Правила (приоритет — как в постановке)

1. **Сначала габариты**: любой размер < 10 мм (недомер) или превышение
   450×320×320 мм (перемер) → категория «Не подходит по габаритам» → **C**.
   Перемерный цилиндр уходит в C, а не в D — приоритет правил соблюден.
2. **Затем форма**: круг в сечении по формальному критерию
   `r_вписанной / R_описанной > 0.8` → «Требует доупаковки» → **D**.
3. Иначе → «Подходит для сортировки» → **B**.

**Метрологические охранные полосы (guard bands).** Сертификация «больше
10 мм» честна только с учетом разрешения измерителя: порог недомера =
10 мм + 2×GSD → **16 мм** для обзорной камеры и **10.8 мм** для макро-камеры.
Куб 11 мм сертифицируется как сортируемый (B) ТОЛЬКО потому, что его измерила
макро-камера; куб 10 мм и стержень Ø9 мм уходят в C. Перемер проверяется по
нижней доверительной границе размеров (25-й перцентиль по чтениям) — смаз
кадра не может «раздуть» товар в перемер.

**Политики безопасной стороны** (все ошибки — консервативные, в C/D/REVIEW,
никогда в B): нет валидных чтений → D; вытянутый предмет с неподтвержденным
сечением → D; слабая, но устойчивая круговая улика → D; сомнение в захвате
кадра (обрезанное/устаревшее облако) → кадр отбрасывается целиком.

### 2.3 Проверки и разбор ошибок

* Официальный набор из 11 STL: классификация **1.0 (66/66, 6 сидов)** на
  номинальных прогонах Isaac (6 сидов), воспроизводимо по сидам.
* Пограничный набор (создан скриптами, размеры документированы): кубы 11/10 мм,
  стержень Ø9, карта 2 мм, коробки 445/460 мм, r/R 0.78/0.82, стержень
  16×12 мм — поведение каждого зафиксировано в матрице валидации.
* Разобранные консервативные решения (документированы как проектные):
  `bl_rod_b` (сечение 16×12 на пороге разрешения флангового датчика) → D;
  `bl_rsq_b` (r/R = 0.78, в 0.02 от порога) → D при стресс-нагрузке;
  сросшиеся облака при плотном потоке → C/REVIEW. Ни одна ошибка не ведет в B.

## 3. Исполнительная часть

### 3.1 Почему поворотные лотки

Правила делают куб 11 мм **легальным сортируемым товаром**. Роликовый
дивертер (ARB) физически не управляет предметами меньше ~50–75 мм (шаг
роликов). У tilt-tray сортировщика товар едет **на собственном лотке** и
сбрасывается гравитацией — сброс **не зависит от размера**: куб 11 мм и пуф
489 мм проходят одинаково. «Поворотные лотки» — класс механизмов, прямо
названный в постановке; это же решение используется в реальной посылочной
сортации.

### 3.2 Полный цикл (все контактной физикой)

выпуск эскейпмента (синхронно с пустым лотком) → сход с ножевой кромки
(падение 60 мм, оффсет посадки измеряется по каждому товару) → перевозка на
подвешенном на реальном шарнире лотке (привод: позиционный, задержка 40 мс,
рампа 160°/с, шум усиления 1%) → позиционный триггер сброса → гравитационный
сход: C/D — юг, в 32°-желоба с полированным листом (μ/tg32° = 0.45 — ничего
не может остановиться на склоне), тормозной площадкой и ролл-кейджем с
апертурой; B — север, через приводной наклонный коннектор (16.6°, товар
держится трением: категория B по правилам не содержит круглых) на
фиксированную ленту; REVIEW — север, в загон ручного разбора. Лоток
возвращается в горизонталь — цикл замкнут (возврат механизма в исходное
состояние — критерий рубрики).

### 3.3 Расчеты ↔ симуляция

Каждый механизм обоснован аналитически и сверен с измерениями в симуляции
(полная сверка: `docs/report/calculations_vs_simulation.md`): угол сброса
38° > угла трогания 17.7°; синхронизация выпуска (модель разгона, в т.ч.
**качения** для лежащих стержней: a_roll ≈ 0.42·a_slide); запас команды
(command margin) ≥ 0.95 с; скорость входа в кейдж ≈ 2.3 м/с с
тормозной площадкой; удержание на наклоне B (0.55 > 0.30); сертификация
мелочи (пол 10.8 мм); производительность.

### 3.4 Нештатные ситуации — у каждого отказа спроектированный безопасный терминал

| Отказ | Реакция (все в матрице валидации) |
|---|---|
| Неуверенная классификация | Полоса REVIEW, не B |
| Товар не сел на лоток (промах индукции) | Каретка и ее сосед помечаются «подозрительными» → профилактический сброс в REVIEW на следующем круге |
| Сброс не подтвержден | Таймаут «застрявшего наклона» → выравнивание → повтор на следующей станции / REVIEW |
| Мертвый привод лотка (дрель `--inject-tray-fault D`) | Товар доезжает до конца линии → вызов оператора (end-line call-out) |
| Застревание в желобе (дрель `--inject-jam`) | Ноль-смещение-вотчдог → джем-камера локализует → манипулятор переносит маршрутно-корректно в СВОЙ кейдж; станция блокируется на время работ |
| Сход мимо устья (поздний/короткий сброс) | Аварийные поддоны вдоль обоих флангов сброса (южный охватывает пьедестал манипулятора воротником 8 мм, южный борт 120 мм, демпфирующая накладка): товар ложится НА поддон — пол конструктивно недостижим — вотчдог поддона вызывает оператора |
| Затор на коннекторе B (дрель) | Вызов оператора, без вмешательства манипулятора |
| Плотный поток / сдвоенная посадка | Спейсинг-гейт + REVIEW при двойной занятости |

### 3.5 Безопасность эксплуатации

Ячейка ограждена, доступ человека — через световую завесу с цепью аварийного
останова; манипулятор стоит на пьедестале в сервисном коридоре МЕЖДУ
желобами C и D (вне объемов всех кейджей) и никогда не пересекает их стенки:
возвращенный товар отпускается на линию желоба СНАРУЖИ стеночной плоскости
и заезжает в кейдж через штатную апертуру — желоб и есть «дверь» кейджа.
Привод наклона рассчитан по худшему удару посадки свипа массы 1.3×
(насыщение 150 Н·м). Зазоры механизма проверяет автоматический аудит
(isaac/audit_clearance.py): полный цикл наклона на каждой станции + конверт
траекторий манипулятора против всей статики, порог 15 мм, ненулевой выход
при нарушении. Все
вызовы оператора выводятся на HMI-лампы станций и андон-колонну; сервисный
режим — пониженная скорость. (Модель ограждений и HMI — в презентационном
слое сцены.)

## 4. Связь частей: категория → управляющее воздействие

Цепочка на каждый товар (пишется в `events.csv` каждого прогона):
`item_classified` (вердикт + уверенность, **до** эскейпмента — упреждение
скрывает латентность инференса) → `escapement_release` (выбор конкретного
пустого лотка по петлевой координате, модель разгона по классу товара) →
`induction_landed` (оффсет посадки, мм) → `routing_cmd` → `tilt_cmd` (момент
позиционного триггера, с упреждением по измеренной длине) → `tilt_full` →
`discharge_confirmed` (подтверждение стороной сброса) → `item_delivered` +
`containment_final`. Запас времени между готовностью команды и дедлайном
триггера — **command margin** — измеряется по каждому товару; минимум по
матрице 0.95 с (отрицательный запас валит прогон ненулевым кодом).

## 5. Производительность и временная согласованность

* Темп ленты 1 м/с, лента не останавливается: `conveyor_a_stop_count = 0` —
  метрика в каждом прогоне.
* Пропускная способность: ≈ 480–500 товаров/час на официальной смеси
  (кейс масштабирования — параллельные ячейки, см. отчет по потоку).
* Cycle time: p95 8.9 (MuJoCo p95; Isaac — те же события, тайминги в summary.json каждого прогона) с (полный цикл: классификация → решение →
  физическая доставка).
* Синхронизация: классификация в движении с упреждением; актуатор — задержка
  40 мс + рампа 160°/с + шум 1%; посадочный оффсет ≤ 131 (номинал; максимум по всей матрице 170) мм.

## 6. Валидация (два движка, одна ячейка)

**Isaac Sim (основной твин, RTX-сенсоры в контуре):** матрица из 14 прогонов
— 6 номинальных сидов, 2 прогона пограничного набора, 4 робастность-свипа
(трение 0.7×, масса 1.3×, плотный поток, смещенная подача), 2 аварийные
дрели. Итог: 14/14 прогонов, **GATES: PASS** — номинальная классификация 1.0 (66/66), номинальная маршрутизация 1.0, 0 опасных ошибок, 0 падений на пол, удержание 1.0, 0 прямых записей скорости, min запас команды 0.95 с, куб 11 мм измерен 11.0 мм (порог 10.8) и доставлен в B. Жесткие гейты консолидации:
классификация ≥ 0.98 (номинал), маршрутизация ≥ 0.97 (номинал), **0 опасных
ошибок, 0 падений на пол, удержание 1.0, 0 прямых записей скорости, запас
команды > 0, куб 11 мм физически доставлен в B**.

**MuJoCo (валидационный твин):** матрица 22 прогона × гейты
(22/22 прогона PASS, 235 товаров, 0 отказов), детерминирован, воспроизводим на машине жюри без
GPU. Совпадение физических огибающих двух движков — самостоятельное
свидетельство валидности (посадочные оффсеты, времена наклона, скорости
входа в кейджи).

Историческая честность: пройденный путь отладки (провал маленького предмета
в дискретный зазор, «совок» при выравнивании лотка, клин тонкой оболочки)
задокументирован в `isaac/README.md` и коммитах — каждый дефект закрыт
проектным решением и **закреплен автотестом-инвариантом** (72 теста).

## 7. Проверка экспертами

Одна команда — вся матрица с гейтами (выход ненулевой при любом провале):

```bash
# MuJoCo (любая машина, CPU):
python -m cell.validate --matrix configs/validation_matrix.yaml
# Isaac (GPU-сервер, официальный контейнер isaac-sim:6.0.1):
bash isaac/run_matrix.sh /out/xbelt_matrix && python3 tools/consolidate_isaac_matrix.py /out/xbelt_matrix
```

Параметры, доступные эксперту: `--seed`, `--items` (любой поднабор, в т.ч.
пограничные), `--manifest-extra` (кубы 11/10 мм и др.), `--spawn-gap`,
`--spawn-offset-y`, `--friction-mult`, `--mass-mult`, `--inject-jam SLUG@Y`,
`--inject-tray-fault ZONE`, `--record` (видео), `--depth-stills` (кадры
сенсоров). Полная инструкция: `README.md §8`, `isaac/README.md`.

## 8. Ограничения и развитие

* Тяговая цепь сортировщика позиционно-управляемая (кинематика по расписанию
  цепи); лоток, шарнир, привод и ВСЕ взаимодействия с товаром — силовые.
  Честная граница модели описана в `isaac/README.md`.
* Мягкие товары (мешок, пуф) — жесткие аппроксимации с материалами
  повышенного трения/демпфирования.
* Манипулятор — кинематические визуальные звенья над валидированным
  4-осевым IK-контроллером; перенос груза — жесткой сцепкой (weld).
* Развитие: физический стенд одного модуля лотка (наибольший прирост УГТ),
  сканер штрихкодов в станции измерения, обучаемый детектор для трекинга
  (категория ВСЕГДА остается за формальными правилами).
